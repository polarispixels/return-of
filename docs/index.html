Return Of Docs

Docs

Return Of is a personal study book on investing and trading. This page explains how the site is put together so that adding a page, a chart, or a new style stays quick.

How the site is laid out

Plain HTML, CSS, and a little JavaScript. There is nothing to install: open index.html in a browser and it works. One small script builds the chapter pages, and its output is saved in the repo.

  • index.html: the welcome page.
  • content/chapters.json: the book's parts and chapters, in order.
  • content/chapters/: one file of content per chapter. This is where the writing happens.
  • chapters/: the finished chapter pages. Built by a script: do not edit them by hand.
  • tools/build.js: builds the chapter pages and the contents list.
  • docs/index.html: this page.
  • css/themes.css: one block of values per style.
  • css/site.css: layout and components. It reads theme values and never hard-codes a color or font.
  • js/version.js: the version number, in one place.
  • js/chart.js: every chart, plus the arithmetic behind them.
  • tools/check.js: the checks that gate every deploy.

How styles work

Styles are tools for a job, not one skin for the whole site. Contemporary Editorial is the voice of the book. Swiss Modernism is the voice of tables, charts, and numbers. Others can join when a new kind of content calls for one.

A style applies to whatever element carries a data-style attribute, and styles nest. The page is Editorial; a figure inside it can be Swiss:

<html data-style="editorial">
  ...
  <figure class="figure" data-style="swiss">
    ...
  </figure>

To add a style, copy a block in css/themes.css, rename it, and change the values. To restyle a page or a block, change one word. The values come from the style profiles in the Visual Design Laboratory.

There are three styles so far: editorial for the book, swiss for tables and charts, and private, a neon pink used only to mark content that is held back (see What is public and what is private).

How chapters work

The book's outline lives in content/chapters.json: five parts, sixteen chapters, each with a title and a one-line summary. Each chapter's writing lives in its own file, such as content/chapters/01-return-of-capital.html. That file holds only the chapter's content: headings, paragraphs, lists, and figures.

Running node tools/build.js wraps each content file in the shared page (header, chapter number, title, previous and next links, footer) and writes it to chapters/. It also rewrites the contents list on the welcome page.

  • To edit a chapter: change its file in content/chapters/, then run the build.
  • To add, rename, or reorder chapters: change content/chapters.json, name the content file to match (number, then the slug), then run the build.
  • Tables: write Table as the figure number and the build numbers it for you (Table 4.1, Table 4.2).
  • Charts: a chapter that asks for a chart gets the chart script added to its page.
  • Drafts: every chapter page is marked "Preliminary draft" for now.

The deploy check fails if a chapter has no content file, if a built page is out of date, or if a content file breaks the rules (for example, it carries its own styles).

Two rules for content: no invented numbers (arithmetic examples are labeled as arithmetic), and nothing personal (no balances, holdings, or past trades). The chapters are study notes, not financial advice, and every chapter page says so.

What is public and what is private

This site is public, and so is its repo. Anything in it can be read by anyone, so the line is drawn before content goes in, not after.

TierWhat goes thereWhere it lives
PublicThe method: principles, rules, arithmetic, the strategy menu, the evaluation dimensions, and judgments that describe no one's accountsThis site
PrivatePersonal choices: which platform does which job in a real portfolio, notes on fees and cash rates, policy numbers, journal resultsNot on this site yet. A pink "Private" box marks the spot
NeverBalances, statements, holdings, account numbersNever on any site

A private block is a placeholder and nothing more: the held-back content is not in the page, the repo, or any file the site serves. To add one to a chapter:

<aside class="private" data-style="private">
  <p class="private-label">Private</p>
  <p class="private-title">What is held back</p>
  <p>One or two sentences on what will appear here.</p>
</aside>

Showing private content to a logged-in reader needs a server, which this site does not have. That is a later step, recorded in the decisions below.

The platform fit matrix

Chapter 13 shows a table of platforms scored against strategies. Its data lives in content/data/platform-fit.json: the strategies with their default weights, and each platform with its scores (0 to 3) and a short role. A chapter asks for the table with the comment <!-- include: platform-fit -->, and the build draws it, sorted by weighted fit.

  • The table is complete without JavaScript. js/matrix.js adds the live part: change a weight and the rows re-rank.
  • The data is a snapshot of a private working sheet, taken by hand. It carries only public fields, and the deploy check rejects any others.
  • The check also recomputes every weighted fit and compares it with the sheet, to catch copying mistakes.
  • To refresh it: update the JSON from the sheet, update the expected figures in tools/check.js, change the "as of" date, and run the build.

How charts work

All charts live in js/chart.js. A page asks for one by name, and the script draws it into that element:

<div class="chart" data-chart="breakeven"></div>

The welcome page uses compound (Fig. 1, what one dollar becomes) and breakeven (Fig. 2, the gain needed to recover a loss). Chapter 14 uses pdt-timeline, settlement, holding-line, loss-carry, wash-sale, sixty-forty, and proposal; its figures show no tax rates and claim nothing beyond the linked sources. Chapter 13 uses tool-order, dimensions, portable, and fit-columns; fit-columns reads the fit matrix table on its page rather than holding its own copy. Chapter 12 uses day-ring, checklist, journal-entry, journal-math, and watched. Chapter 11 uses calm-check, traps, revenge, restraint, and adherence. Chapter 10 uses exit-plan, ratchet, sized-trades, tug-of-war, and streaks; the sized trades live in SIZED, checked against the chapter’s table. Chapter 9 uses holding-periods, long-call, tuition-months, paper-gate, and trade-cap. Chapter 8 uses option-roles, covered-call, short-put, wheel, and covered; the Wheel figure’s numbers live in WHEEL, and the check fails if they drift from the chapter’s table. Chapter 7 uses attention-month, setups, momentum-funnel, trade-plan, and running-expectancy. Chapter 5 uses ladder, promotion, time-decay, tuition, and neglect. Chapter 4 uses tags, menu-grid, loss-shape, effort-shapes, groups, and attention; its strategy list lives in STRATEGIES in js/chart.js, and the check fails if it drifts from the chapter’s table. Chapter 3 uses edge-chain, cost-waterfall, memory, expectancy-map, and edge-loop. Chapter 1 uses round-trip, breakeven-curve, survivors, habits, and questions. Chapter 2 uses recovery, buckets, cushion, and satellite-cap. Chapter 6 uses fees, pie, dividend-loop, dividend-income, drift, hedge, and core-default. To add one, write a draw function and add it to the CHARTS list at the bottom of the file.

There are two kinds of figure. Charts show numbers on axes and carry data-style="swiss". Diagrams show a mechanism with shapes, arrows, and short labels; a diagram with no numbers may carry the page's Editorial style instead. Both are drawn by the same file and share its small kit: text, arrow, arrowhead, donut, box, chip (a numbered strategy circle), hGrid, polyline, and spread (keeps end labels apart). Below about 420px wide, charts show fewer ticks and drop labels the caption already covers.

Color has one meaning across the book. Black (--fg) is the main path and the core. Red (--accent) is loss, cost, risk, or the active slice: the satellite and the casino floor. Blue (--accent-2, with a light tint --accent-2-soft) is the other category: other holdings, the cushion and reserve, the alternative being compared, a reference line. Blue never means loss or gain. Gray (--muted) is structure only: grids, axis labels, bands, and empty states. A good outcome is never red, and a neutral holding is never red.

The aim is a figure for every section of a chapter, working with its text: sometimes a summary, sometimes a step further. Figures in a chapter are numbered by chapter (Fig. 6.1, 6.2, and so on), and a chapter that uses one example across figures keeps its colors fixed per holding. Across the book, the buckets keep one color each: core black (--fg), satellite red (--accent), cushion blue (--accent-2), reserve light blue (--accent-2-soft).

  • Charts are drawn at the real width of their container, not scaled, so labels stay readable on a phone. They redraw when the window changes size.
  • Charts take their colors and fonts from the style of the figure they sit in.
  • The arithmetic (grow, breakeven) is kept apart from the drawing, and tools/check.js tests it on every deploy. The check also fails if a page asks for a chart that does not exist.
  • Two figures meant to be read together go in a <section class="pair">: side by side on a wide screen, stacked on a phone.
  • Every figure says where its numbers come from. Arithmetic is labeled as arithmetic.

Versioning and releases

The site follows SemVer and keeps a changelog. The version shows in the footer of the welcome page and at the top of this one, so a deploy can be checked by eye.

  1. Bump RETURN_OF_VERSION in js/version.js.
  2. Add a ## [x.y.z] entry to CHANGELOG.md.
  3. Run node tools/build.js, then node tools/check.js.
  4. Commit, push to main, then tag: git tag vX.Y.Z && git push --tags.

How it ships

Every push to main runs the checks in GitHub Actions. If they pass, the same workflow publishes the site to GitHub Pages. A failing check never reaches the live site. A deploy is done when the live page shows the new version.

Backlog and issues

Work is tracked in GitHub Issues. Each issue carries one MoSCoW label, one effort label, and one type label. Loose ideas that are not yet issues live in BACKLOG.md.

Decisions

  • November 19, 2026: plain static files, no build step. Fastest way to start, and easy to outgrow. The tradeoff: shared pieces like the header are copied between pages until a generator is worth adding.
  • November 19, 2026: styles are scoped by data-style, not chosen once per site. Lets a Swiss chart sit in an Editorial page. The tradeoff: components may only use theme values, never their own colors or fonts.
  • November 19, 2026: hosted on GitHub Pages, deployed by GitHub Actions. Free, public, and gated by the checks. A polarispixels.com subdomain can point here later.
  • November 19, 2026: charts are hand-drawn SVG, no chart library. One chart does not justify a dependency. Revisit when charts multiply.
  • November 19, 2026: one chart file with a registry, and the arithmetic tested in the deploy check. Adding a chart is one function and one line. The tradeoff: every page that shows any chart loads the code for all of them, which is fine while there are few.
  • November 19, 2026: Fig. 2 is paired bars on one plain scale, for losses from 10% to 90%. Putting the loss and the gain needed on the same scale makes the point without prose: the loss bars barely move while the gain bars run away. The tradeoff: the small losses are slivers, so each row also prints its number. A log scale would show them better but would hide the very thing the figure is about.
  • November 19, 2026: the epigraph is attributed "Often attributed to Will Rogers", with its real history beside it. The note says only what the linked Quote Investigator article supports, and quotes the 1920 advertisement in its own words.
  • November 19, 2026: a small build script for chapters, with its output saved in the repo. Sixteen pages share one header and footer, so copying by hand stopped making sense. Chapters are now plain content files and a script with no dependencies wraps them. Saving the output keeps the site openable straight from the files; the tradeoff is that the build must be run before a commit, which the deploy check enforces. This replaces the "no build step" decision above for chapter pages only.
  • November 19, 2026: the contents list lives on the welcome page. A book opens to its title page and then its contents. The tradeoff is a longer welcome page, with the two thesis figures now below the contents.
  • November 19, 2026: all sixteen chapters ship as preliminary drafts. They are built from the book plan plus well-established fundamentals, and each ends with open questions still to be answered. The tax and regulation notes in Chapter 14 are checked against primary sources and linked.
  • November 19, 2026: three tiers of content, and private blocks are placeholders for now. Real privacy needs a server and a login, which means moving off GitHub Pages and running an app. That is deferred. Until then, anything personal stays out of the repo entirely and a pink "Private" box marks where it will go. The tradeoff: nothing private can be read on the site, even by its author.
  • November 19, 2026: the platform fit matrix is public; the recommended stack is private. Scores say how well a tool suits a strategy and describe no one's accounts. The stack, and the notes on fees and cash rates behind it, describe a real portfolio and go stale quickly, so they are held back.
  • November 20, 2026: charts get a second color, blue. Black, red, and gray alone made multi-series charts read as grayscale. Blue was chosen over green and purple after a side-by-side preview: it stays distinct from the red for colorblind readers (green scored lowest next to red in the palette validator), and it does not read as “gain.” The tradeoff: the Swiss profile in the Laboratory calls for one accent, so --accent-2 and --accent-2-soft are a book-specific extension in css/themes.css, not Laboratory values.
  • November 20, 2026: the Protective Hedge (Strategy 8) lives in Chapter 6, The Core. The book plan rated it but gave it no chapter. Its job is to insure the core, so it sits beside the core, before “Why the core is the default.” The tradeoff: Chapter 6 grows a section instead of the book growing a chapter, which would have renumbered every chapter after it.
  • November 20, 2026: a figure for every section, starting with Chapter 6. Chapter 6 is the test case for the look of the whole book. Diagrams are drawn in code like charts, not as image files, so they follow the theme and stay readable on a phone. The tradeoff: each diagram is a small program, slower to make than a sketch. Design notes: docs/superpowers/specs/2026-11-20-chapter-6-figures-design.md.
  • November 20, 2026: Chapter 6 figures use one example pie, with labeled arithmetic. 60/30/10 drifted to 67/24/9 connects the pie, the drift, and the next deposit across two figures. The fee and dividend figures use stated assumptions (7% return; 3% yield, 6% payout growth), not real fund data. All are examples, not recommendations.
  • November 19, 2026: the matrix is a dated snapshot built into the page. The working sheet is private and live; the site is static. A snapshot is simple and honest about its date. The tradeoff: it must be refreshed by hand when the sheet changes.
